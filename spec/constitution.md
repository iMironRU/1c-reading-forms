# Конституция книги

> Контракт с читателем и ограничитель для автора.
> Claude Code читает этот файл перед каждым действием.

---

## Что эта книга ЕСТЬ

- **Третья книга линии «Чтение 1С».** Книга 1 учит читать код, книга 2 —
  дерево метаданных, книга 3 — форму (поверхность системы, её лицо), книга 4 —
  данные (язык запросов).
- Учебник **чтения формы как структуры**: читатель открывает незнакомую форму и
  называет все её части — реквизиты, элементы, команды.
- Практикум: читатель работает одновременно в Конфигураторе и в режиме
  «1С:Предприятие», надевая формы на конфигурацию «Канцтовары».
- Книга о **замысле автора формы**: почему элемент устроен именно так.

## Что эта книга НЕ ЕСТЬ

- **Не книга о коде.** Обработчики событий не разбираются: во всех формах книги
  они пусты и помечены `// для книги: обработчики намеренно пусты`. Это
  принципиальная граница.
- **Не разбор директив компиляции** `&НаКлиенте` / `&НаСервере` — вводим
  концепцию клиента и сервера, но не код.
- **Не курс по системе компоновки данных** — только обзорно, в модуле про отчёты.
- **Не про обычные (неуправляемые) формы** — одно упоминание в Модуле 0 и всё.

## Метафора книги

**Форма — это разговор системы с пользователем по поводу одного объекта.**

| В естественном языке | В интерфейсе 1С |
|---|---|
| реплика | форма |
| предмет реплики | реквизит формы |
| видимая часть реплики | элемент формы |
| глагол | команда |
| оглавление книги | командный интерфейс |

Пять уровней — ровно столько, сколько работает в книге. Расширять метафору на
«абзацы» и «сценарии» не будем: это удваивает терминологию без выигрыша.

```
Форма            → реплика системы по поводу одного объекта
Реквизит формы   → предмет реплики («о чём разговор»)
Основной реквизит→ главный предмет (сам объект — товар, документ)
Элемент формы    → видимая часть реплики
Поле             → «вот данные» (показ) или «введите данные» (приём)
Группа           → смысловой блок реплики
Декорация        → пояснение (надпись, картинка)
Таблица          → список однотипных строк
Команда          → доступное действие, глагол
Кнопка           → визуальный носитель команды
Командная панель → список глаголов, доступных в этом месте
```

### Граница метафоры (даётся читателю явно)

Метафора точно описывает формы справочников, документов, отчётов. Но есть
**формы-организаторы** — обработки, рабочие места, панели мониторинга: у них
либо нет основного объекта, либо он не главный. Их цель не «один предмет», а
«целая задача». Оговорка вводится микро-семенем в §0.3, повторяется при каждом
упоминании обработок и разворачивается отдельным параграфом в Модуле 9 — чтобы
читатель не получил шок, открыв форму, которая «не вписывается».

## Четыре несущих принципа

Появляются в Модуле 0 и работают до Модуля 10.

1. **Разговор.** Форма — реплика о одном объекте (см. выше).
2. **Автогенерация из метаданных.** Не задана форма явно — платформа строит её
   сама из дерева. Отсюда правило: пока хватает автогенерации, своего не делаем.
3. **Клиент и сервер.** Данные живут на сервере, пользователь — на клиенте.
   *Парная строгая формулировка:* сама форма не «путешествует», она живёт на
   клиенте; между клиентом и сервером ходят данные и запросы.
4. **Декларативность.** Мы не пишем «когда нажмётся кнопка — сделать то-то», мы
   задаём правила, по которым платформа сама строит и оживляет интерфейс.

### Якорные правила первого ряда

> Форма — это разговор системы с пользователем по поводу одного объекта.

> Если форма не задана явно — платформа создаёт её из метаданных.

> Если форма ведёт себя сама — значит, где-то в дереве задано правило.

> Данные живут на сервере, пользователь — на клиенте. Между ними — постоянное
> путешествие данных и запросов; сама форма находится на клиенте.

## Принципы изложения

1. **Парная строгая формулировка — в усиленном режиме.** Каждая метафора
   немедленно сопровождается строгой версией **с привязкой к конкретной вкладке,
   свойству или действию в редакторе**: «Поле — это вопрос системы к
   пользователю. Строже — элемент формы с путём к данным; в редакторе поле живёт
   на вкладке „Элементы“, а его данные настраиваются на вкладке „Реквизиты“».
   Без такой пары метафора становится убежищем от реальности платформы, а её
   задача — реальность подсвечивать.
2. **Никаких абсолютов** «без X нет Y».
3. **Бытовое слово, затем строгий термин:** «поле (элемент формы для показа или
   ввода значения реквизита)».
4. **ASCII-схемы трёх видов:** фрагмент дерева метаданных, структура формы (три
   области), скетч экрана глазами пользователя.

## Терминологическая развилка (строго)

**Реквизит объекта** (в дереве метаданных) и **реквизит формы** (в данных формы)
— разные вещи. Различаются с §3.1 и не смешиваются нигде.

## Технические решения (зафиксированы)

- Платформа — **1С:Предприятие 8.5**. Названия пунктов меню и поведение
  автогенерации проверяются на ней.
- Режим форм — **только управляемые**.
- **Ни строки кода обработчиков.**
- Конфигурация-приложение «Чужие формы»: серия из 7–8 форм, проходит через все
  модули начиная со второго.

## Что автор не будет делать никогда

- Не писать код обработчиков и не разбирать директивы компиляции.
- Не оставлять метафору без строгой пары с привязкой к редактору.
- Не смешивать реквизит объекта и реквизит формы.
- Не опираться на интуицию читателя из веба, мобильных или офисных интерфейсов:
  управляемая форма устроена иначе.
- Не использовать эмодзи, цветные блоки, кричащую вёрстку.

## Аудитория (кратко)

**Читатель:** абсолютный новичок без опыта программирования. Знакомство с
деревом метаданных желательно, но не обязательно — Модуль 0 даёт минимальный
обзор для пришедших сразу сюда.

**Читатель НЕ:** веб- или мобильный разработчик, ищущий аналогий со своим
стеком; действующий 1С-разработчик за справочником по свойствам формы.

Полное описание — в `spec/specification.md`, полный план — `docs/00_plan_knigi.md`.
